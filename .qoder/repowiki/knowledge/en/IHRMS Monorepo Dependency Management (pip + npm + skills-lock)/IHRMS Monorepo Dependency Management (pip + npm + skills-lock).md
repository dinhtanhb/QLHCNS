## Approach

The IHRMS monorepo manages dependencies across three distinct layers, each with its own tooling and lockfile:

1. **Python backend** — `requirements.txt` with exact pinning (`==`) for every package.
2. **Node.js frontend** — `package.json` + `package-lock.json` managed by npm; only Tailwind CSS tooling is declared as a dependency.
3. **Agent skills** — `skills-lock.json` pins third-party Claude Code / Agents.md skills from the `mattpocock/skills` GitHub repository by computed SHA hash.

There is no Go module, no Poetry/uv lockfile, no vendored Python packages, and no private PyPI registry configured in this repo. All third-party code comes from public registries (PyPI, npm, GitHub).

## Key Files

- `requirements.txt` — single flat list of pinned Python dependencies (Django 5.2.17, mssql-django, pyodbc, msal, reportlab, django-jazzmin, etc.).
- `package.json` — declares only `@tailwindcss/cli` 4.3.0 and `tailwindcss` 4.3.0 under `devDependencies`; scripts build Tailwind CSS into `src/static/css/tailwind.css`.
- `package-lock.json` — npm lockfile generated by npm (used via `npm ci` in CI).
- `skills-lock.json` — custom lockfile tracking ~30 skills from `mattpocock/skills`, each entry carrying `source`, `sourceType: "github"`, `skillPath`, and a `computedHash` of the skill content.
- `.github/workflows/ci.yml` — orchestrates dependency installation and auditing for both backends.
- `.github/workflows/sqlserver-regression.yml` — installs deps against a SQL Server service container.

## Architecture and Conventions

### Python dependencies
- Every package in `requirements.txt` uses an exact version pin (`==`). There are no ranges, no `constraints.txt`, no `setup.py`/`pyproject.toml` at the repo root.
- The CI step `python -m pip check` enforces that the installed set is mutually consistent after `pip install -r requirements.txt`.
- A disposable SQLite database is used for all regression runs (`DB_ENGINE=sqlite3`), so no system-level DB driver is required on the default CI runner.

### Node.js dependencies
- Only two dev-only packages are declared: `@tailwindcss/cli` and `tailwindcss`, both pinned to `4.3.0`. No runtime JS dependencies exist at the repo root.
- CI uses `npm ci` (not `npm install`) to enforce the lockfile, then runs `npm audit --audit-level=low` as a gate.
- The build script `build:css` compiles `src/frontend/tailwind.input.css` → `src/static/css/tailwind.css` (minified); there is no bundler or framework dependency.

### Agent skills
- Skills are not installed via npm/pip; they are checked out from `mattpocock/skills` on GitHub and locked by `skills-lock.json`.
- Each skill entry records the source repo, the path inside it, and a `computedHash` of the skill's content, providing integrity verification beyond a branch/tag reference.

## Enforcement in CI

`.github/workflows/ci.yml` enforces the following dependency-related gates on every push/PR to `main`:

| Layer | Step | Enforcement |
|---|---|---|
| Python | `python -m pip install -r requirements.txt pip-audit==2.9.0` | Installs exact versions plus the auditor itself |
| Python | `python -m pip check` | Fails if transitive resolution conflicts exist |
| Python | `python -m pip_audit -r requirements.txt` | Fails on known CVEs reported by pip-audit |
| Node | `npm ci` | Fails if `package-lock.json` does not match `package.json` |
| Node | `npm audit --audit-level=low` | Fails on any low-severity advisory |
| Node | `npm run build:css` | Fails if the Tailwind build cannot compile the input CSS |

The SQL Server regression workflow additionally installs the Microsoft ODBC 18 driver (`msodbcsql18`, `unixodbc-dev`) from the Microsoft apt repository before installing Python deps, since `mssql-django` requires it.

## Constraints and Rules

- **Exact pinning for Python**: `requirements.txt` uses `==` for every dependency; no loose ranges are present.
- **Lockfiles are mandatory**: CI uses `npm ci` (requires `package-lock.json`) and `pip install -r requirements.txt` (no editable installs). Both must be committed alongside manifest changes.
- **Vulnerability scanning is a CI gate**: `pip-audit` and `npm audit --audit-level=low` will fail the pipeline, so new dependencies must pass both scanners.
- **No private registries or vendoring**: No `.pypirc`, `PIP_INDEX_URL`, `PIP_TRUSTED_HOST`, `PYPI_TOKEN`, `~/.npmrc`, `package.json` `resolutions`/`overrides`, or vendored `vendor/` directories were found. All packages resolve from public PyPI/npm/GitHub.
- **Skills integrity via hash**: `skills-lock.json` stores a `computedHash` per skill rather than a mutable branch ref, anchoring each skill to a specific content revision.
- **Frontend has no runtime deps**: The only `node_modules` contents are Tailwind tooling; the compiled output (`src/static/css/tailwind.css`) is what the Django app ships.
