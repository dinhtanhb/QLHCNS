The module is a flat collection of independent CLI entry points plus three small sub-packages, each owning one operational concern:
- Top-level `run_*.py` / `check_*.py` / `audit_*.py` scripts are self-contained Django-aware CLIs. They bootstrap `config.settings`, set `DJANGO_SETTINGS_MODULE='config.settings'` and `APP_ENV='test'`, then import models from `apps.*` to seed fixtures or assert rendered output.
- `ops/run_tests.py` is the canonical test runner: it picks a backend (`sqlite` | `sqlserver` | `configured`), creates an in-memory SQLite DB or a disposable `test_ihrms_<uuid>` SQL Server database (refusing reuse of the app DB), sets `MEDIA_ROOT` under `tempfile.TemporaryDirectory`, forces `locmem` email backend, and wraps `DiscoverRunner` with a non-empty-suite guard.
- `ops/run_browser_uat.py` and the many `run_*_uat.py` scripts follow the same pattern — Playwright sync API against a `LiveServerThread`, synthetic fixture creation via ORM, screenshot capture to `<output>/screenshots`, and a JSON report written to `<output>/browser-result.json`.
- `ops/check_ui_contrast.py`, `ops/audit_button_kinds.py`, `ops/render_ui_components.py`, `ops/capture_ui_screenshots.py`, `ops/layout_waivers.json` form the UI-design-audit layer: they parse CSS tokens, crawl templates and live pages (via Playwright CDP), compare button kinds/sizes against a JSON contract, and write machine-readable reports outside the repo.
- `ops/check_ui_menu_links.cjs` is a Node 22+ script that launches Edge headless via CDP and validates pointer-click navigation against a synthetic-cases JSON file.
- `ops/reset_qa_data.py` is a guarded SQL Server-only resetter: it rejects any DB name not matching `*_uat_*` or the preview snapshot, requires a `.bak` outside the repo, enforces an `IHRMS_DISPOSABLE_QA=YES` extended property, clears all but a whitelisted catalog of 107 tables, and seeds exactly 33 users (3 per role).
- `ops/backup/` contains PowerShell + T-SQL scripts (`Backup-FullDatabase.ps1`, `Backup-TransactionLog.ps1`, `Test-BackupSafety.ps1`, `Setup-RecoveryModel.sql`) orchestrated by Windows Task Scheduler; `ops/probes/` holds a single Python probe (`booking_status_validation.py`); `ops/scheduler/` has reminder runners invoked by Task Scheduler.
Dependency direction is one-way: ops scripts depend on `src/apps.*` models and `config.settings`; nothing in `src` imports back into `ops`.
