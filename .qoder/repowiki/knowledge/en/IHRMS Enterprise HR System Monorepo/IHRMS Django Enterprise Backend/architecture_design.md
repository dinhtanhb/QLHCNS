Monolithic Django project rooted at `src/` with a single `config/` package (`settings.py`, `urls.py`, `wsgi.py`, `asgi.py`) wiring ~20 domain apps under `apps/`. Each app follows the standard Django layout (`models.py`, `views.py`, `admin.py`, `migrations/`, `tests.py`, optional `services.py`, `management.commands/`). The root URL dispatcher in `config/urls.py` mounts only three top-level namespaces — `/portal/`, `/reports/`, `/assistant/` — plus `/admin/` and a private-file proxy; all other apps are reached through those namespaces. `apps.common` provides shared infrastructure: `BaseAuditModel` + `SoftDeleteManager`/`SoftDeleteQuerySet` for soft-delete auditing, `ApplyDueEmployeeChangesMiddleware`, templating tags (`ui_numbers`, `ui_components`), upload helpers, and UI choice/status enums. `apps.security` is the cross-cutting security layer: custom `User`/`Role` models extending `AbstractUser`, RBAC permission checks, `SensitiveResponseMiddleware`, `PrivateFileStorage`, login lockout via `django-axes`, and audit event logging. `apps.portal` is the main web surface (large template tree under `templates/portal/`, view modules split by domain like `hr.py`, `finance.py`, `recruitment.py`, `dashboard_data.py`, `home_presentation.py`). `apps.document.hcns` is a self-contained sub-package implementing Vietnamese official-document rendering (layout profiles, prefill, PDF export). Cross-app communication uses direct model imports and explicit service functions rather than an ORM abstraction layer; background work is triggered via management commands (e.g. `send_activity_report_reminders`, `apply_due_employee_changes`, `send_lifecycle_reminders`, `purge_search_logs`). Database defaults to SQLite (`db.sqlite3`) but switches to SQL Server via `mssql` when `DB_ENGINE` is set, with production enforcing encrypted connections.
